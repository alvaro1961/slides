From Math to Code

  • Previously, we used Keras to define and train neural networks.
  • In Keras, model.fit() performs the forward pass, loss computation, backpropagation, and parameter updates automatically.
  • This simplifies model training but hides the underlying optimization steps.
  • In this section, we use PyTorch, where the model architecture and training loop are written explicitly.
  • Before examining the code, we review the mathematical principles underlying the training process.

Optimization on \(\mathbb{R}^n\)

  • Suppose that our model parameters be represented as a vector \(\mathbf{w} \in \mathbb{R}^n\).
  • Our goal is to minimize the loss function \(\mathcal{L}: \mathbb{R}^n \to \mathbb{R}\). That is, we want to find \(\mathbf{w}^*\) such that: \(\quad\mathbf{w}^* = \arg\min_{\mathbf{w}} \mathcal{L}(\mathbf{w})\)
  • The minimum satisfies \(\nabla\mathcal{L}(\mathbf{w}^*)=0\) and we approximate solutions using Gradient Descent (or variations)
  • Recall that the gradient \(\nabla \mathcal{L}(\mathbf{w})=\left(\frac{\partial \mathcal{L}}{\partial w_1},\dots,\frac{\partial \mathcal{L}}{\partial w_n}\right)^T\) points in the direction of steepest ascent.
  • To minimize \(\mathcal{L}(\mathbf{w})\), the optimization algorithms travels against this vector.
  • The Step: We initialize randomly at \(\mathbf{w}^{(0)}\) and iteratively update parameters using a learning rate \(\eta > 0\): \[\mathbf{w}^{(k+1)} = \mathbf{w}^{(k)} - \eta \nabla \mathcal{L}\left(\mathbf{w}^{(k)}\right)\]

The Core Training Loop

Training a neural network consists of repeatedly executing three steps:

  1. The Forward Pass (Evaluate)
    • We pass input features through the model to calculate the current prediction and evaluate the loss function value: \(\mathcal{L}(\mathbf{w}^{(k)})\).
  2. The Backward Pass (Find Gradient)
    • We calculate the gradient vector \(\nabla \mathcal{L}(\mathbf{w}^{(k)})\).
    • PyTorch performs automatic differentiation to compute these partial derivatives for all parameters.
  3. The Parameter Update (Step)
    • The optimizer takes the computed gradient and steps against it to update the vector: \(\mathbf{w}^{(k+1)} = \mathbf{w}^{(k)} - \eta \nabla \mathcal{L}(\mathbf{w}^{(k)})\).

In implementation, the forward pass is split into prediction and loss computation.

Automatic Differentiation

  • Tensors & Gradients
  • Computational Graph
  • Backward Pass
  • Core Data Structure: PyTorch represents data as torch.Tensor objects, multi-dimensional arrays that support hardware acceleration and automatic differentiation.
  • Gradient Tracking: Setting requires_grad=True tells PyTorch to track operations involving the tensor.
  • Leaf Tensors: Tensors created directly by the user (such as parameters w and b) are leaf tensors and serve as the independent variables in the computational graph.
  • Gradient Storage (.grad): Initially None, this attribute stores the gradient computed during backpropagation. Gradients accumulate unless explicitly cleared.
  • Gradient Function (.grad_fn): Tensors produced by operations have a .grad_fn attribute that records the operation used to create them, allowing PyTorch to traverse the computational graph during backpropagation.

When a tensor has requires_grad=True, PyTorch builds a computational graph that records how operations compose together. The example here is:

  • \(\text{loss} = (z-1)^2\) where
  • \(w=-1.5\), \(b=0.5\), and \(z=2w+b\)
import torch
from torchviz import make_dot

# Tensors tracking gradients
x = torch.tensor(2.0)
w = torch.tensor(-1.5, requires_grad=True)
b = torch.tensor(0.5, requires_grad=True)

# Forward pass tracks operations
z = w * x + b
loss = (z - 1.0)**2

# Visualizes the dynamic DAG
make_dot(loss, params={'w': w, 'b': b})
  • Calling loss.backward() initiates backpropagation.
  • PyTorch then traverses the computational graph in reverse, applying the Chain Rule to compute the gradient of the loss with respect to every parameter.
  • These gradients are stored in the .grad attribute of each parameter (w.grad and b.grad in this example)
  • Gradients accumulate by default. If we call loss.backward() repeatedly, the gradients add to the existing ones. unless they are explicitly cleared (e.g., w.zero_grad()).
  • To find the partial derivatives, \(\frac{\partial\text{loss}}{\partial w}\), \(\frac{\partial\text{loss}}{\partial w}\) we use w.grad, b.grad:
# Compute gradients via backpropagation
loss.backward()

# The computed gradients are stored (and accumulated) in .grad
w.grad, b.grad
(tensor(-14.), tensor(-7.))

Why Automatic Differentiation Matters

  • Neural networks may contain millions of trainable parameters.
  • Computing partial derivatives by hand is infeasible.
  • PyTorch’s autograd system constructs a computational graph during the forward pass and uses reverse-mode automatic differentiation to efficiently compute all gradients with a single backward pass.

Note

Automatic differentiation computes exact derivatives (up to floating-point precision), unlike numerical differentiation, while requiring work proportional to the forward computation.

Defining a Model in PyTorch

PyTorch models can be built directly by stacking layers linearly using nn.Sequential.

This is the same neural network from Presentation 4

import torch
import torch.nn as nn
model = nn.Sequential(
            nn.Linear(1, 32),
            nn.ReLU(),
            nn.Linear(32, 32),
            nn.ReLU(),
            nn.Linear(32, 1)
        )
print(model)

  (0): Linear(in_features=1, out_features=32, bias=True)

  (3): ReLU()
  (4): Linear(in_features=32, out_features=1, bias=True)
)

Running the Forward Pass: To pass data through this network, you simply evaluate a tensor of the right dimension directly into the model object as if it were a function:

Counting Parameters

total_params = sum(p.numel() for p in model.parameters())

Total trainable parameters: 1153

Each nn.Linear(in, out) layer has \(\text{in} \times \text{out}\) weights plus \(\text{out}\) biases.

For our network: \((1 \times 32 + 32) + (32 \times 32 + 32) + (32 \times 1 + 1) = 1,153\) parameters.

This is small by any standard. A modern language model has billions.

But the training loop is identical — the same four moves, regardless of scale.

The Training Loop

Everything in PyTorch training maps to four steps:

for epoch in range(num_epochs):

    # 1. Forward pass: compute predictions
    y_pred = model(X)

    # 2. Compute loss
    loss = loss_fn(y_pred, y)

    # 3. Backward pass: compute gradients
    optimizer.zero_grad()
    loss.backward()

    # 4. Optimizer step: update parameters
    optimizer.step()
  • Forward pass — run data through the network
  • Loss — measure how wrong the predictions are
  • Backward pass — compute gradients via autodiff
  • Optimizer step — move parameters in the direction that reduces loss

optimizer.zero_grad() clears gradients from the previous iteration. By default PyTorch accumulates gradients — forgetting this is a common bug.

What the Optimizer Is Doing

The optimizer implements gradient descent:

\[\theta \leftarrow \theta - \eta \, \nabla_\theta \mathcal{L}\]

  • \(\theta\) — the parameters (weights and biases)
  • \(\eta\) — the learning rate (step size)
  • \(\nabla_\theta \mathcal{L}\) — the gradient, computed by .backward()

This is the same minimization from Presentation 1 — we are still minimizing an empirical loss.

The only difference is scale: millions of parameters instead of a handful.

# Stochastic Gradient Descent
optimizer = optim.SGD(model.parameters(), lr=0.01)

# Adam: adaptive learning rates, usually converges faster
optimizer = optim.Adam(model.parameters(), lr=0.001)

Adam is the default choice for most neural network training — it adapts the learning rate for each parameter individually, making it more robust than plain SGD.

Defining Models using Classes

We use custom Python classes inheriting from nn.Module to build and reuse architectures.

  • When you use a class, you must define the forward(self, x) method. This tells PyTorch exactly how your input data moves through your layers.
  • You write def forward(), but you never call model.forward(x) in your code. You just run model(x). PyTorch handles the execution under the hood and tracks it on the graph.
#| echo: false
class SimpleNet(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, output_dim)
        )

    def forward(self, x):
        return self.layers(x)

Capacity and Overfitting

The same bias–variance tradeoff from Presentation 1 applies here.

# Small network: may underfit
model_small = SimpleNet(input_dim=1, hidden_dim=4, output_dim=1)

# Large network: may overfit
model_large = SimpleNet(input_dim=1, hidden_dim=512, output_dim=1)

More capacity means the network can fit more complex functions — but without regularization or early stopping, it will memorize the training data.

The tools are the same: validation sets, regularization, careful model selection.

Classification in PyTorch

The same pattern applies to classification. The loss changes from MSE to cross-entropy.

# Binary classification: spiral data
torch.manual_seed(0)
np.random.seed(0)

n = 200
theta = np.linspace(0, 4 * np.pi, n)
r     = np.linspace(0.1, 1, n)

X0 = np.column_stack([r * np.cos(theta),       r * np.sin(theta)])
X1 = np.column_stack([r * np.cos(theta + np.pi), r * np.sin(theta + np.pi)])

X_cls = torch.tensor(np.vstack([X0, X1]), dtype=torch.float32)
y_cls = torch.tensor([0] * n + [1] * n,  dtype=torch.long)
model_cls = SimpleNet(input_dim=2, hidden_dim=64, output_dim=2)
loss_fn   = nn.CrossEntropyLoss()          # softmax + cross-entropy
optimizer = optim.Adam(model_cls.parameters(), lr=0.01)

for epoch in range(2000):
    logits = model_cls(X_cls)
    loss   = loss_fn(logits, y_cls)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

nn.CrossEntropyLoss combines softmax and cross-entropy in one step — the same loss from Presentation 2, now applied inside the training loop.

Classification Results

The same network that fits a sine wave can separate a spiral — because stacking layers with activations produces functions expressive enough to approximate any continuous boundary.

Putting It Together

Each PyTorch component corresponds to a concept from earlier:

PyTorch concept Earlier idea
requires_grad, .backward() Chain rule from calculus
MSE loss Empirical risk minimization (Presentation 1)
Cross-entropy loss Maximum likelihood (Presentation 2)
optimizer.step() Gradient-based optimization
Validation loss Bias–variance tradeoff (Presentation 1)
nn.Module Parameterized function class

PyTorch implements these mathematical ideas in an automated and scalable form: it records operations, computes gradients via reverse-mode automatic differentiation, and applies optimization updates over many parameters.
